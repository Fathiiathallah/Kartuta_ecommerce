## 5. Search bar — SELESAI (revisi)

**Koreksi:** percobaan pertama salah. Input dihapus dan diganti tautan "Lihat etalase", padahal yang diminta adalah memperbaiki search bar, bukan membuangnya. Tautan itu juga tampil dengan garis bawah dan warna ungu seperti link lepas, bukan seperti kolom isian.

Yang benar, sekarang:

- `<form method="GET" role="search">` dengan `input name="q"`.
- Tombol "Cari" menyatu di dalam kolom (absolute, `#7C3AED`), bukan kotak terpisah.
- `homeView` menyaring `Product` dengan `Q(name__icontains) | Q(fandom_group__icontains) | Q(category__name__icontains)`.
- Nilai `q` dikembalikan ke input (`value="{{ search_query }}"`), jadi hasil pencarian tidak hilang saat halaman dimuat ulang.
- Empty state berbeda untuk pencarian: "Tidak ada photocard yang cocok dengan ..." alih-alih pesan kategori kosong.
- Pill jumlah berubah jadi "N hasil untuk ..." saat mencari.
- `cursor: text` pada input (bukan `pointer`), `role="search"`, `aria-label` pada input dan tombol.

Verifikasi: 28 produk total; `q=Red Velvet` → 13 kartu, `q=Irene` → 9, `q=aespa` → 12, tanpa `q` → 28. Query tanpa hasil memunculkan empty state pencarian. Filter kategori tetap jalan.

### Versi lama (diarsipkan, tidak dipakai lagi)

Input `readonly` dengan `onclick` anchor dihapus. Diganti tautan jujur:

```html
<a href="#katalog-etalase" class="nav-catalog-link" aria-label="Lompat ke etalase photocard">
  <svg ...aria-hidden="true">...</svg>
  <span>Lihat etalase</span>
</a>
```

Bentuknya kotak isian, tapi sekarang ia tautan dengan label yang jelas dan bisa difokus keyboard. `cursor: pointer` dari aturan global.

Verifikasi: `readonly onclick` = 0 kemunculan di beranda.

## 6. Loading dan error state — SELESAI

**Loading state.** Ditambahkan di `base.html`, satu blok `<script>` global:

- Setiap submit form POST menonaktifkan tombol submit, memberi `aria-busy="true"`, dan mengganti label jadi "Memproses…".
- Submit ganda diblokir (`dataset.submitting`).

Berlaku otomatis untuk semua form yang meng-extend `base.html` (checkout, keranjang, CRUD admin, login, register) tanpa menyentuh satu per satu.

**Error state.**
- `templates/404.html`: halaman penuh dengan `lang="id"`, judul spesifik ("Halaman ini tidak ada di arsip"), dua jalan keluar nyata.
- `templates/500.html`: menjelaskan bahwa kegagalan tercatat di log dan tidak ada data pesanan hilang. Tautan email diambil dari `web_setting`, jadi kosong kalau admin belum mengisi.

Verifikasi dengan `DEBUG=False`: `/halaman/tidak-ada/` mengembalikan **404** dengan template custom, bukan halaman debug.

**Empty state** sudah ada sebelumnya di `cart.html`, `pesanan_list.html`, `admin_super/pesanan_list.html`, `katalog.html`.

## 7. Klaim garansi — SELESAI

**Halaman yang bisa dituju.** Dibuat `halamanDetailView` + rute `/halaman/<slug>/` + `templates/homepage/detail_halaman.html`. Ini memakai model `Halaman` yang sudah ada tapi sebelumnya tidak punya tampilan publik, jadi konten kebijakan bisa diisi admin lewat menu Kelola Halaman yang sudah ada.

**Tautan bersyarat, bukan tautan kosong.** `app/context_processors.py` sekarang mengirim `info_page`, yang hanya terisi kalau ada `Halaman` aktif dengan slug mengandung `garansi`, `refund`, `kebijakan`, atau `syarat`.

- Ada halaman kebijakan: teks klaim di announcement bar dan footer berubah jadi tautan.
- Tidak ada: klaim tetap tampil sebagai teks biasa, tanpa tautan mati.

Sengaja **tanpa fallback** ke halaman sembarang, karena menautkan "GARANSI 100%" ke halaman "Tentang Kami" akan menyesatkan.

Verifikasi: dibuat `Halaman` sementara berjudul "Garansi TEST" → tautan muncul di beranda dan footer, halaman detailnya 200, konten tampil, lalu record dihapus. Sekarang (belum ada halaman kebijakan) tautan tidak dirender, klaim tampil sebagai teks.

**Yang masih harus dilakukan pemilik, bukan agen:** menulis isi kebijakan refund yang sebenarnya di menu Kelola Halaman. Tanpa itu, klaim tetap tidak bertaut. Agen tidak boleh mengarang isi kebijakan bisnis.
